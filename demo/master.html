How a message gets routed

Customer sends a message on the Chat page | v chatbot.py -- RAG over product docs + full company/policy context decides one of: RESOLVED | RESOLVING | RAISE_TICKET | ESCALATE_HUMAN | +----+-------------------+------------------------+ | | | RESOLVED RAISE_TICKET ESCALATE_HUMAN no action (technical or not) human handover | | | | +-----------+-----------+ | | | | | | technical non-technical | | v v v | normalizer.py support_hub.py support_hub.py | (terminology) enqueue_ticket() enqueue_handover() | v | | | issue_engine.py +------+------+ | cluster by cosine v | similarity, bump weight support.db | v (Developer Queue / Agent Workspace) | issues.db | v | webhook: ticket.created (skipped if this was a retried/duplicate request) | v | webhook_outbox row written durably, delivery attempted immediately. | Failure? Retried with backoff by a background thread - never | silently dropped. See GET /webhooks/outbox on the Developer Queue page. v session closed

Try it yourself

1. Copy the API key printed in the server's console output (or set TACKETY_API_KEY in engine/.env for a stable one) and paste it into the nav bar above.

2. Upload your company/product/policy docs in the Knowledge Base Setup panel above - without them the chatbot has no context and will answer generically.

3. Open the Chat page and describe an issue - try a technical bug ("checkout is crashing") vs. a billing question ("I want a refund") vs. "let me talk to a human". Each routes differently, and the chat page shows you the raw engine response for every message.

4. Open the Developer Queue to see technical clusters ranked by urgency, and the Agent Workspace to see (and resolve) non-technical cases and live handovers.
